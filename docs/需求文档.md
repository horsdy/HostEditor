# HostEditor 需求文档

- 文档版本：v0.1
- 编写日期：2026-10-16
- 阶段：需求基线；实现与验证进展见 [开发与验收记录](开发与验收记录.md)。
- 产品名称：HostEditor

## 1. 产品目标

开发一款运行于 Apple Silicon Mac 的原生图形化 hosts 编辑器。用户可以从 macOS 顶部菜单栏打开主窗口，以具有语法高亮的原生文本编辑器修改 `/etc/hosts`，通过清晰的系统授权流程保存受保护文件，并配置主题和 hosts 文件路径。

软件应适配本机硬件架构和操作系统；不依赖 Rosetta、浏览器运行时或 Web 技术栈。

## 2. 平台与范围

| 项目 | 要求 |
| --- | --- |
| 首要验收环境 | 当前检测环境：arm64、macOS 26.6.1（25G76） |
| 硬件架构 | 主程序及权限辅助组件均提供原生 arm64 构建 |
| 最低系统版本 | 暂定 macOS 13.0；属于建议基线，须通过兼容性验证后才能声明支持 |
| 开发语言 | Swift；确有系统接口需要时允许少量 Objective-C/C |
| 界面技术 | AppKit / SwiftUI；编辑器采用原生文本组件 |
| 禁止使用 | Electron、Tauri、HTML/CSS/JavaScript 界面、WebView 编辑器以及其他 Web 应用外壳 |
| 使用方式 | 本机离线使用，无账号要求 |
| 界面语言 | 首版简体中文 |
| 分发方式 | 提供包含独立 `.app` 的 arm64 `.dmg` 安装包；正式分发使用签名与公证；Mac App Store 不属于首版目标 |

当前环境信息仅说明需求编写时的检测结果，不代表软件已经完成运行验证。首版必须在本机完成真实读写、权限授权和菜单栏交互验收。

## 3. 首版范围与默认决策

### 3.1 必须交付

1. 读取、编辑、校验和保存默认 `/etc/hosts`。
2. 图形化获取所需权限，并提供授权状态、失败原因和恢复入口。
3. hosts 语法高亮、行号、等宽字体和单一原生文本编辑模式。
4. 设置窗口：深色、浅色、跟随系统三种主题选项，hosts 文件路径和权限管理。
5. 关于窗口：版本、构建号、硬件架构与当前 macOS 信息。
6. 菜单栏常驻图标：左键显示主窗口，右键打开菜单。
7. 未保存修改保护、保存前备份和外部修改冲突检测。
8. 应用包、可执行程序与菜单栏共用统一设计的斜体 H 图标，体现 hosts 映射编辑用途。
9. 按钮与标签不以省略号表示截断或待操作；仅“选择文件...”保留省略号。

### 3.2 不纳入首版

- vi / Vim 模式、命令模式及 Vim 命令兼容。
- hosts 配置分组、订阅下载、云同步、多配置合并和远程主机管理。
- 自动刷新 DNS 缓存、代理配置及网络抓包。
- Windows、Linux、Intel Mac 专门适配和 Universal 构建。
- 自动更新、开机启动和多语言界面。

### 3.3 待产品确认的默认值

为便于后续直接实施，本文采用以下暂定决策；这些决策不阻塞需求文档交付：

- 编辑器采用单一普通文本编辑模式，遵循 macOS 原生文本编辑器的键盘、选择、输入与撤销习惯。
- 首次启动显示主窗口；之后关闭主窗口仍保留菜单栏图标。
- 主题默认值已确认：首次启动默认深色，支持深色、浅色、跟随系统三种选项；选择跟随系统后，随系统外观变化动态切换，用户选择在重启后保留。
- 不自动保存到目标 hosts 文件；写入必须由用户显式触发。
- 首版单主窗口、单活动文件；切换路径需要处理当前未保存修改。

## 4. 功能需求

### 4.1 文件读取与路径选择

**F-01 默认文件**

- 初次启动读取 `/etc/hosts`，主窗口持续显示当前路径。
- 路径解析需要识别系统正常的路径别名，例如 `/etc/hosts` 与 `/private/etc/hosts`，避免误认为两个不同文件。
- 以纯文本方式读取；保留注释、空行、条目顺序和原有空白，不自动整理或删除未知内容。
- 支持 UTF-8 文本；保留原有换行风格和文件末尾换行状态。无法可靠解码时显示原因并禁止有损覆盖。

**F-02 自定义路径**

- 设置中提供路径输入框、“选择文件...”和“恢复默认路径”。
- 用户选择的是本地普通文本文件；目录、设备、套接字及不可安全访问的目标不得作为编辑对象。
- 文件不存在时明确提示；不静默创建 `/etc/hosts` 或其他目标文件。
- 点击“应用”前先验证可读性和文件类型，再处理未保存修改；切换失败保留原路径与编辑内容。
- 可写的自定义文件直接保存；受保护的自定义文件进入与默认文件相同的授权流程。
- 自定义路径仅决定编辑和保存目标。界面说明：只有操作系统实际使用的 hosts 文件才会影响本机解析。

### 4.2 原生文本编辑与语法高亮

**F-03 基础编辑**

- 支持鼠标定位、选择、复制、粘贴、撤销、重做及查找。
- 显示行号、当前行、光标行列与修改标记。
- 使用系统可用的等宽字体；首版不要求字体配置功能。
- 禁用自动富文本、智能引号、自动替换等会改变配置文本的行为。
- 高亮与校验只改变显示效果，不改变文件内容或污染撤销历史。

**F-04 高亮规则**

| 内容 | 识别与呈现 |
| --- | --- |
| IPv4 / IPv6 地址 | 地址色；正确支持 IPv6 中的冒号 |
| 主机名及别名 | 与地址、注释区分的颜色 |
| `#` 注释 | 从 `#` 到行末显示为注释，包括行尾注释 |
| 空行、空格、Tab | 保持原内容；空格与 Tab 均可作为字段分隔 |
| 明确的语法错误 | 下划线或错误标记，并提供可读说明 |

深色与浅色主题分别提供可辨识的配色，错误提示不能只依赖颜色。

### 4.3 文本编辑与查找

**F-05 单一原生编辑模式**

应用提供单一普通文本编辑模式，不提供 vi / Vim 模式切换或命令行输入区。

- 使用原生 `NSTextView` 支持文字输入、方向键、鼠标选择、复制、粘贴、撤销、重做及中文输入法。
- `⌘S` 保存、`⌘F` 查找、`⌘Z` 撤销、`⇧⌘Z` 重做及常用剪贴板快捷键均有效。
- `⌘,` 打开设置，`⌘W` 关闭当前窗口，`⌘Q` 退出应用。
- `⌘F` 显示原生查找栏；若编辑器中存在选中文本，将其填入查找输入框。
- 查找栏打开时按 `Esc` 隐藏查找栏并返回编辑器。

### 4.4 权限与保存

**F-07 权限状态与引导**

- 主窗口区分“可直接保存”“保存需要授权”“等待系统批准”“授权服务不可用”“文件不可访问”等状态。
- 可读但暂时不可写时，允许先编辑；保存入口显示所需授权步骤。
- 提供“授权写入”入口。首次使用受保护文件时解释用途，再调用系统支持的授权机制。
- 开发签名版本可以通过 macOS 管理员认证执行限于当前目标的一次性写入；可信签名版本可采用系统管理的后台辅助组件。若系统要求用户批准后台辅助组件，提供“打开系统设置”及文字指引；返回应用后重新检查状态。
- 不自行收集或存储管理员密码；不要求以 root 身份启动整个图形应用。
- 不通过永久放宽 hosts 权限、关闭 SIP 或要求用户运行终端命令来完成常规授权。
- 取消、拒绝、非管理员用户无法取得所需批准、辅助组件被禁用等情况均保留编辑内容，并给出重试或导出副本入口。
- 设置提供权限状态与重新检查入口；仅安装了受信任签名辅助组件时才显示系统设置和卸载入口。卸载后仍可读取可访问文件并编辑普通可写文件。

**F-08 保存事务**

用户点击保存或按 `⌘S` 时，使用同一保存流程：

1. 判断内容是否改变；没有变化则显示无需保存，不发起不必要的授权。
2. 执行语法校验，并处理阻断错误或警告。
3. 检测磁盘文件是否与本次打开或上次保存时的版本一致。
4. 检查权限；必要时完成系统批准及受限辅助组件调用。
5. 保存当前磁盘版本的备份；备份失败则中止此次覆盖并说明原因。
6. 以安全的替换方式写入，避免留下半截文件；保留原文件所有者、权限及可保留的 ACL、扩展属性。
7. 确认写入结果后更新文件基线和修改标记，并显示保存成功。

磁盘空间不足、权限变化、辅助组件退出或目标文件被替换时不得报告成功。失败必须保留缓冲区，并确保目标仍为完整旧版本或完整新版本；需要恢复时提供明确入口。外部修改检测与实际替换之间仍须处理竞争条件，不能只在点击保存时检查一次。

### 4.5 校验、备份与冲突

**F-09 hosts 校验**

- 有效映射行为：一个 IPv4/IPv6 地址，后跟至少一个主机名，可含多个别名及行尾注释。
- 接受空行、纯注释行，以及使用多个空格或 Tab 的有效条目。
- 无效 IP、缺失主机名、意外控制字符等确定错误显示行号，阻止覆盖保存；仍允许导出编辑副本。
- 重复映射、同一主机名对应不同地址等作为警告，解释原因后允许用户确认保存；同一主机名同时配置 IPv4/IPv6 本身不应判为错误。
- 对不确定的主机名形式给出警告，避免过度严格的规则误拦合法现有配置。
- 不自动删除、合并或重排条目；用户打开已有错误文件时仍能查看并修正。

**F-10 备份与恢复**

- 每次实际覆盖前保存旧版本，按目标文件隔离；每个文件默认保留最近 20 份成功备份，淘汰旧备份只能在新备份成功后执行。
- 备份位于应用管理的本地目录，使用限制访问的权限；不上传、不记录到普通日志。
- 主窗口提供“备份与恢复”入口，列出时间及目标路径，并可查看内容。
- 恢复前处理当前未保存修改；恢复写入同样执行权限检查、冲突检查和当前磁盘版本备份。历史备份按原样恢复，不被新校验规则静默改写。
- 若目标路径变化导致无法确认原文件身份，不自动将备份恢复到其他文件。

**F-11 外部修改与未保存保护**

- 监听目标文件变化，并在窗口重新激活与保存前复核文件状态。
- 无本地修改时可以自动重新读取，并提示文件已更新；有本地修改时保留缓冲区并标记冲突。
- 冲突时允许查看磁盘版本、重新加载或导出当前编辑副本；首版不支持自动合并和强制覆盖冲突版本。
- 关闭主窗口、退出应用、切换路径、重新加载或恢复备份时，若存在未保存修改，提供“保存 / 不保存 / 取消”。
- 选择保存后，只有保存成功才能继续原动作；取消授权或保存失败均停留在原编辑状态。

### 4.6 主窗口、菜单栏与应用生命周期

**F-12 主窗口**

主窗口从上到下包含：

1. 顶部工具栏：副标题“本机 hosts 编辑器”左侧显示，当前文件路径紧邻其右侧；不显示大号 HostEditor 标题；保存、重新加载、备份与恢复、设置操作靠右。
2. 权限或冲突提示区：仅在需要用户行动时出现。
3. 编辑区：行号、原生文本编辑器和语法高亮。
4. 底部状态栏：行列、未保存状态和校验结果。

主窗口支持调整大小，建议初始大小约 960 × 640；最小尺寸下仍能访问保存、设置及错误提示。

**F-13 顶部菜单栏图标**

| 操作 | 必须行为 |
| --- | --- |
| 左键点击 | 显示并激活主窗口；已打开则置前，已最小化则恢复；重复点击不重复创建窗口 |
| 右键点击 | 在图标处弹出菜单，不同时触发主窗口显示 |
| Control + 左键 | 与右键行为一致 |
| 关闭主窗口 | 完成未保存检查后隐藏/关闭窗口，应用继续运行，图标保留 |
| 退出应用 | 完成未保存检查后退出，移除图标；辅助组件生命周期独立管理 |

- 菜单项：打开主窗口、保存、设置、关于、退出 HostEditor。
- 保存项根据有无修改、权限和操作进行状态显示；保存进行中避免重复提交。
- 图标适配系统菜单栏的深浅外观，与编辑器主题设置分别处理。
- 图标提示显示应用名称及是否存在未保存修改，不泄露 hosts 内容。
- 首版采用普通 macOS 应用形态，启动后在 Dock 显示应用图标，同时保留菜单栏图标；关闭主窗口后应用继续运行，点击 Dock 图标可重新打开主窗口。

### 4.7 设置与关于

**F-14 设置窗口**

| 设置项 | 行为 |
| --- | --- |
| 主题 | 深色、浅色、跟随系统；首次启动默认深色。选择后即时生效，覆盖主窗口、编辑器、设置与关于窗口；跟随系统时动态响应系统外观变化，固定深色/浅色不受系统变化影响 |
| hosts 路径 | 显示当前路径，支持输入、文件选择、恢复默认；应用后重新读取目标 |
| 权限管理 | 状态、授权/重新检查、系统设置指引、卸载辅助组件 |

主题和有效路径在重启后保留。无效路径不覆盖已保存的有效配置。设置在文件选择对话框等系统控制的界面上遵循系统行为，不强求自定义主题。

**F-15 关于窗口**

- 显示应用名称、版本、构建号、版权及许可证信息。
- 显示作者联系信息：`Author: houlake@gmail.com`。
- 显示硬件架构和以“系统信息：macOS x.y.z”标识的当前 macOS 版本，方便核实本机兼容性。
- 窗口中的所有文字均支持选中和复制。
- 可选展示项目主页；没有真实地址时不显示虚构链接。

## 5. 非功能需求

### 5.1 原生实现与权限边界

- 建议采用 Swift + AppKit，或 SwiftUI 配合 AppKit；编辑器以 `NSTextView` / TextKit 实现，菜单栏以 `NSStatusItem` 实现。
- 受信任签名版本可使用 `SMAppService` 管理辅助组件并通过受限 XPC 通信；开发签名版本使用 macOS 管理员认证执行经校验的单次目标写入，不注册常驻 root 服务。
- 图形应用使用普通用户权限；辅助组件只处理已明确授权的 hosts 目标文件及对应备份操作。
- 两种授权路径均验证目标版本和路径，仅提供 hosts 保存操作，不提供任意命令执行或任意文件读写接口。
- 添加受保护自定义路径需要每次明确的系统管理员认证，不能仅凭普通设置值扩大提权范围。
- 对目标路径规范化、符号链接与文件身份变化进行校验，防止授权后重定向到其他文件；默认系统路径别名应正常支持。
- 本机编译可使用开发签名；正式分发的主程序和辅助组件须使用一致的受信任签名方案，并完成公证与干净环境验证。
- 正式分发的辅助组件须使用一致的受信任签名方案并完成公证与干净环境验证；开发版的单次认证流程不代表完成正式分发验收。

系统认证由 macOS 呈现；认证缓存和提示频率以当前系统行为为准，应用不承诺长期或跨操作免认证。

### 5.2 性能与可靠性

- 在首要验收机器上，100 KB 测试文件的冷启动到可编辑目标为 2 秒以内；需记录实际测试结果。
- 在 1 MB 测试文件上，连续输入、滚动及高亮不应出现持续超过 100 ms 的主线程阻塞；采用增量处理及后台校验。
- 文件超过 1 MB 时提示性能风险，用户可继续打开；不得在未说明的情况下截断内容。
- 授权、校验、读取和保存期间提供明确状态，耗时任务不得使整个窗口失去响应。
- 常驻空闲时不忙轮询，不因隐藏主窗口而反复读文件。

### 5.3 隐私与可访问性

- 核心功能离线完成，默认不上传 hosts、备份、文件路径或设备信息。
- 日志记录操作结果和错误码，避免包含 hosts 正文、认证信息及其他敏感内容。
- 主要按钮与菜单具有可访问性标签；支持键盘导航及 VoiceOver 读取模式、权限与错误状态。
- 两种主题均保证正文、注释和选中内容可辨识；校验结果有文字描述。

## 6. 验收标准

涉及默认 hosts 写入的测试必须先建立可恢复备份，并在测试后恢复原始内容及权限；日常编辑测试优先使用临时副本。

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| A-01 | 本机原生运行 | 在 arm64 / macOS 26.6.1 启动，主程序及辅助组件为 arm64，无 Rosetta 和 Web 运行时依赖 |
| A-02 | 首次读取 | 默认打开 `/etc/hosts`，路径、原文、行号及权限状态正确 |
| A-03 | 高亮 | IPv4、IPv6、多别名、行尾注释、Tab 和空行显示正确，高亮不改动正文 |
| A-04 | 原生编辑模式 | 使用原生文本输入、选择、撤销、重做和中文输入，无 vi 命令拦截 |

## 7. 实施顺序与交付物

1. **需求阶段**：交付本文，确定首版范围、默认决策与验收标准。
2. **原型与权限验证**：验证原生编辑器、菜单栏左右键行为，以及本机上的签名、辅助组件批准、写入和卸载闭环。
3. **核心开发**：完成原生编辑、高亮、查找、路径与主题设置、关于窗口。
4. **数据保护**：完成统一保存流程、校验、备份恢复、外部冲突和失败处理。
5. **验收与分发**：交付 arm64 应用、源代码、构建说明、权限使用说明和验收记录；具备签名条件后交付可正式分发的安装包。

优先验证权限闭环，因为它直接决定默认 `/etc/hosts` 能否在普通用户启动的图形界面中可靠保存。
